## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → local node_modules | Supply-chain ingestion of `@vercel/speed-insights` and transitive deps via `npm install`. |
| Browser → Vercel telemetry endpoint | At runtime, `<SpeedInsights />` posts Web Vitals (LCP, CLS, INP, FCP, TTFB) plus path / userAgent fragments to a Vercel-managed beacon endpoint. Telemetry leaves the user's browser. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25.1-SC | Tampering (Supply Chain) | `npm install @vercel/speed-insights` (Task 2) | mitigate | Blocking human checkpoint (Task 1) verifies the package is published by the `vercel` org on npmjs.com before Task 2 runs `npm install`. Lockfile (`package-lock.json`) pins the resolution. No `npm audit fix` side-effects in this phase. |
| T-25.1-01 | Information Disclosure | `<SpeedInsights />` runtime beacon | accept | Vercel-published library; data sent is limited to Web Vitals metric values, the route path, and standard browser metadata — no auth tokens, user emails, or collection data. PERF-06 explicitly requires this telemetry. Disposition: accept. |
| T-25.1-02 | Tampering (XSS via third-party script) | `<SpeedInsights />` injected client script | accept | Component is a React component from a Vercel-published package, not a runtime `<script src>` injection. Same trust posture as any other dependency rendered in the layout (`NavBar`, `NuqsAdapter`). Already covered by T-25.1-SC. |
| T-25.1-03 | Repudiation / Spoofing | Telemetry origin authenticity | accept | Telemetry sink is Vercel's own infrastructure; the project must be deployed on Vercel for the beacon to authenticate (PERF-06 dashboard step). No mitigation required at the app layer. |
| T-25.1-04 | Denial of Service | `<SpeedInsights />` blocking critical rendering path | accept | Component is implemented as a no-op outside Vercel deployments and uses passive listeners. Render impact is negligible by design. Verification step (Task 4) catches console errors that would indicate breakage. |
| T-25.1-05 | Elevation of Privilege | n/a | n/a | No new privileged surface introduced. No server routes, no auth changes, no DB writes. |

ASVS L1 review: no high-severity threats identified. Supply-chain risk is mitigated by the blocking-human checkpoint (Task 1) per planner Package Legitimacy Gate. Information disclosure is intentional (PERF-06 mandates it) and limited to Web Vitals metadata.
</threat_model>
