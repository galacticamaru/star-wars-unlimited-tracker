# Phase 25.1: Speed Insights Integration - Context

**Gathered:** 2026-05-27
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 25.1 installs and configures `@vercel/speed-insights` so every page in the app emits Web Vitals data to the Vercel dashboard in production. The implementation is two files:

1. `package.json` — add `@vercel/speed-insights` as a dependency (`npm install @vercel/speed-insights`)
2. `src/app/layout.tsx` — import and render `<SpeedInsights />` inside `<body>`

No new UI features, no database changes, no API routes. This is a zero-footprint instrumentation install.

</domain>

<decisions>
## Implementation Decisions

### Sample Rate
- **D-01:** Use the default 100% sample rate — no `sampleRate` prop needed. The app has a small user base; sampling down would lose signal without meaningful cost savings.

### Route Exclusion
- **D-02:** No route exclusions — no `beforeSend` hook. All page routes are tracked. API routes are automatically excluded by the library (it only instruments page navigations).

### Debug Panel
- **D-03:** Enable the debug panel in development by passing `debug={true}` to `<SpeedInsights />`. This lets the team verify data collection locally before relying on the Vercel dashboard after a production deploy.

### Claude's Discretion
- Exact placement of `<SpeedInsights />` within `<body>` (before or after existing children — convention is after, as the last child)
- Whether to conditionally set `debug` via `process.env.NODE_ENV === 'development'` expression or just hardcode `debug={true}` (either is fine; conditional is marginally cleaner)

</decisions>
