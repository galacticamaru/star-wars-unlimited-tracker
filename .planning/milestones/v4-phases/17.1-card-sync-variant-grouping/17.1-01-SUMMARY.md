**Single-pass in-memory Map grouping replaces two-pass DB-lookup strategy in upsertCards, eliminating orphaned card_definition rows and adding self-healing cardDefinitionId propagation on re-seed**

## Accomplishments
- Replaced the two-pass Pass1/Pass2 structure (255 lines) with a clean in-memory grouping loop (117 lines)
- All variants of the same logical card are now grouped by `Name.trim()|Subtitle.trim()` before any DB operation — no DB name+subtitle query inside the loop
- Anchor selection prefers Normal variant; falls back to lexicographic min collectorNumber for promo-only cards (no Normal exists)
- `cardDefinitionId` added to `card_printings` onConflictDoUpdate set — re-seeding now self-heals previously orphaned rows from the old two-pass bug
- TypeScript compiles clean (npx tsc --noEmit exits 0)
- `syncAllCards`, `SWUCard`, `SWUSet`, `parseIntOrNull` all unchanged

## Files Created/Modified

## Decisions Made
- Group key is `Name.trim()|Subtitle.trim()` — handles all variant types uniformly without needing any DB reads in the hot path
- Anchor collectorNumber (`Set-Number` of Normal or lexicographic min variant) becomes the `swudbId` for `card_definitions` — preserves all existing Normal-variant swudbId values
- Retained unused imports (`eq`, `and`, `isNull`) from drizzle-orm since `noUnusedLocals` is not set in tsconfig.json — minimizes diff noise
- `cardDefinitionId: sql\`excluded.card_definition_id\`` added to card_printings conflict update set — this is the key self-healing fix that resolves the original orphaned-rows data integrity bug
