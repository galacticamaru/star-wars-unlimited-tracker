<objective>
Implement PERF-07: per-user cache tagging for the two deck read queries, server-side `revalidateTag` invalidation in all three deck mutation handlers, and client-side `router.refresh()` in DecksClient after create/delete success. This makes returning-user /decks loads serve from cache while guaranteeing that create/rename/delete never show stale data on the next load (two-layer invalidation, D-05).

Purpose: Returning users currently re-query the DB on every /decks visit (no cache); after this plan, the deck list and each deck detail are cached per user and only re-fetched after a mutation.
Output: Cached query functions, invalidating route handlers, and refreshing client component — all matching the established catalog.ts / sync-cards.ts conventions.
</objective>
