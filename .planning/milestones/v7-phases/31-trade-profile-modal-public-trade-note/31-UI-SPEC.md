# Phase 31 — UI Design Contract

> Visual and interaction contract for the Trade Profile modal (username + public trade note) and its public-binder callout. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase does not introduce a new design system — it extends existing project tokens and component patterns (`Sheet`, `Input`, `Button`, `buttonVariants`) into two new sibling components (`Dialog`, `Textarea`) built on the same already-installed `@base-ui/react` primitives. All tokens below are the **existing project tokens**, restated as the binding contract for this phase's three UI surfaces (manage-page header button, profile modal, public-binder callout) so the checker and executor have a single source of truth without re-deriving them from `globals.css`.

All copy, structure, and storage decisions below are locked by `.planning/phases/31-trade-profile-modal-public-trade-note/31-CONTEXT.md` (D-01 through D-10) and `31-RESEARCH.md`. This spec resolves only the items CONTEXT.md left to discretion: modal primitive choice, exact button/label wording, icon choice, callout styling, and counter placement.

## Layout Contract

### Surface 1 — Manage page header (`src/app/binder/manage/page.tsx`)
- Header row stays a `flex items-center justify-between` container; the right-hand button group becomes `flex items-center gap-2` with two buttons in this order: **"Trade Profile"** (new, `UserCog` icon, `buttonVariants({ variant: "outline" })`) then **"View Public Binder"** (existing, unchanged, `ExternalLink` icon) — D-03 requires the public-binder link stay visible and unmoved in spirit; placing the new button first (as the "manage" action) keeps the external, leave-the-page link last.
- The inline "Trade Profile" `Card` (existing lines ~372–398, left column) is **deleted entirely** — no placeholder, no empty column gap left behind (D-01). The left column's remaining content (search/add flow, trade offerings grid) shifts up to fill the space naturally via existing `space-y-8`.

### Surface 2 — Profile modal (`src/components/binder/profile-modal.tsx`, new)
- Centered Base UI `Dialog` (RESEARCH.md Pattern 3), `max-w-md`, `rounded-lg border bg-popover p-6 shadow-lg`, backdrop `bg-black/10` + `backdrop-blur-xs`.
- Includes a top-right close (`X`) icon button, matching `SheetContent`'s `showCloseButton` affordance (`variant="ghost" size="icon-sm"`, `absolute top-3 right-3`) — the Dialog is dismissible via close button, `Escape`, and outside click, same as `Sheet`. This button is icon-only (no visible label) and **must** carry `aria-label="Close"` — required, not left to executor discretion.
- Content order top to bottom: `DialogTitle` ("Trade Profile") → `DialogDescription` (one-line description) → username `Input` + public-URL helper paragraph directly beneath it → trade-note `Textarea` (3 rows) + right-aligned character counter directly beneath it → inline error text (only when a save attempt fails) → footer with a single right-aligned **Save Profile** button.
- All fields stacked vertically (`space-y-4`), matching the existing inline Card's `Input` styling — no side-by-side layout (D-08: "full profile in one place", single-column read order).

### Surface 3 — Public binder callout (`src/components/binder/public-binder-client.tsx`)
- Mounts as its own full-width bar directly beneath the existing username header block (`<h1>{username}'s Trade Binder</h1>` container) and above the `flex flex-1` filters/results row — visible before any card content, matching D-06.
- Styling: `px-4 lg:px-8 py-2 bg-muted/20 border-b border-border text-sm text-muted-foreground`, with a small `MessageSquareText` lucide icon (`size-3.5`, `inline-block mr-1.5 align-text-bottom`) preceding the note text to read as a "note/banner" rather than a stray paragraph.
- **When `tradeNote` is null or empty: the entire block, including its container `div`, is absent from the DOM.** Not `hidden`, not `opacity-0`, not an empty bordered box — the conditional wraps the whole element (`{tradeNote && <div>...}</div>}`) so zero layout space is reserved (D-07).

## Interaction Contract

- **Opening the modal:** clicking the header "Trade Profile" button sets local `open` state to `true`; the Dialog mounts via Portal (no page navigation, no route change).
- **Field initialization:** on open, `username` is seeded from `session.user.username` (existing pattern, unchanged) and `tradeNote` is seeded from `session.user.tradeNote ?? ''` — both re-seeded fresh each time the modal opens (not just once on page mount), so stale edits from a previously-cancelled open don't linger.
- **Trade note input:** `onChange` clamps via `e.target.value.slice(0, 140)` in addition to the native `maxLength={140}` attribute (belt-and-suspenders per RESEARCH.md's Textarea example); the counter re-renders on every keystroke from the same state value — no separate debounce needed for a plain character count.
- **Save button enabled state:** disabled while a save is in flight, OR when neither field has changed from its seeded value (`username === session.user.username && tradeNote === (session.user.tradeNote ?? '')`) — extends the existing single-field dirty-check pattern to both fields.
- **Save flow (D-09):** one click calls `authClient.updateUser({ username: username.toLowerCase().trim(), displayUsername: username.trim(), tradeNote: tradeNote.trim() })` in a single request (RESEARCH.md "Full modal save handler"). On success (`!error`): close the modal. On failure (`error` present): keep the modal open, preserve both field values as typed, and show the inline error copy from the Copywriting Contract above — do not clear or reset the form.
- **Closing without saving:** the `X` close button, `Escape`, and outside-click all dismiss the modal without persisting changes (standard Base UI `Dialog` behavior, no custom guard/confirmation — there is no unsaved-changes warning in scope for this phase).
- **Public callout rendering (D-07, XSS-safe):** `tradeNote` is interpolated as plain JSX text (`{tradeNote}`) — never via `dangerouslySetInnerHTML`. React's auto-escaping is the only sanitization needed; no sanitization library is introduced (matches every other user-supplied string already rendered elsewhere in this codebase).
- **Public callout data flow:** `src/app/binder/[username]/page.tsx` (RSC) passes `tradeNote` as a prop down to `PublicBinderClient`, sourced from the extended `getUserIdByUsername` query — no client-side fetch for this value.
