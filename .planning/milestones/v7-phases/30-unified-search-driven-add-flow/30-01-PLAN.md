<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/trade (PATCH) | Authenticated user submits `{ cardPrintingId, tradeQuantity }`; server must authorize per-printing ownership |
| client → /api/binder/wants (POST) | Authenticated user submits `{ cardPrintingId, quantity }`; wants are intentionally allowed for any printing (owned or not) per D-06 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-30-01 | Elevation of Privilege / Broken Access Control | `PATCH /api/trade` | high | mitigate | Task 3 adds a server-side `userPrintingCollections` ownership check (count > 0) before upserting any positive-quantity trade offering; unowned → 403 |
| T-30-02 | Tampering | `VariantWantSection` → `POST /api/binder/wants` | low | accept | Wants are deliberately unrestricted by ownership (D-06/BINDER-14); endpoint already requires a session and scopes writes to `session.user.id` — no new exposure |
| T-30-03 | Information Disclosure | client trade/want steppers | low | accept | Sections receive only the current user's own per-printing counts (already returned by authenticated endpoints); no cross-user data introduced |
| T-30-SC | Tampering (supply chain) | npm installs | low | accept | No new dependencies added this plan (PATTERNS.md confirms zero new packages); no install step to gate |
</threat_model>
