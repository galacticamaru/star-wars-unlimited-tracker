<objective>
Fix the row-overlap bug surfaced by Phase 24 UAT Test 4 (HUMAN-UAT.md). The virtualized CardGrid currently uses a fixed `estimateSize: () => 160`, but real row heights vary with column count: at 3 columns the card is wide and tall (~280px), at 11 columns it is narrow and short (~100px). When the fixed estimate is too small for the actual row height, the absolutely-positioned rows that the virtualizer lays out via `transform: translateY(virtualRow.start)px` overlap each other — cards visually cover other cards.

Purpose: Restore visual correctness of the catalog grid at every breakpoint. PERF-01 (filter interactions ≤200ms) and PERF-03 (no layout shift, no overlap) are not actually met until rows lay out without overlap. The fix is the TanStack Virtual canonical approach for variable-height rows — `measureElement` — combined with a smarter initial `estimateSize` derived from the known card aspect ratio (2:3) and the actual scroll container width.

Output: `card-grid.tsx` calls `useVirtualizer` with both (a) a `measureElement` option using the package's built-in DOM measurement helper and (b) a column-count-aware `estimateSize` function that reads `scrollContainerRef.current?.clientWidth ?? fallback`. Each rendered row `<div>` carries `data-index={virtualRow.index}` and `ref={rowVirtualizer.measureElement}` so the virtualizer can match measurements to virtual items. A new unit test confirms each row has the `data-index` attribute and that `useVirtualizer` is called with a `measureElement` option. Manual verification by the user confirms no overlap at any breakpoint.
</objective>

From node_modules/@tanstack/react-virtual (version 3.13.26, confirmed installed):

- `useVirtualizer(options)` returns a `Virtualizer` instance with:
  - `getTotalSize(): number`
  - `getVirtualItems(): Array<{ index: number; key: number | string; start: number; size: number }>`
  - `measureElement: (node: TItemElement | null) => void` — attach as ref to a rendered row; the virtualizer reads `data-index` from the node and stores the measured height
- `useVirtualizer` options include:
  - `count: number`
  - `getScrollElement: () => Element | null`
  - `estimateSize: (index: number) => number` — REQUIRED; used as the initial height before measurement
  - `overscan?: number`
  - `measureElement?: (element, entry, instance) => number` — OPTIONAL custom measurer. The package also re-exports a default `measureElement` helper at the module level (from `@tanstack/virtual-core`) that uses `getBoundingClientRect().height`. Passing this option enables ResizeObserver-based dynamic measurement of any rendered row that has a `data-index` attribute AND has `ref={rowVirtualizer.measureElement}` attached.

  NOTE: The TanStack canonical pattern is to pass `ref={rowVirtualizer.measureElement}` (the instance method) directly to each row. This implicitly uses the default DOM measurer. An explicit `measureElement` option in the config is only needed for custom logic. The executor should use the instance-method ref pattern — it is simpler and is what TanStack docs prescribe.

Card aspect ratio for estimateSize:
- Container width is read at runtime via `scrollContainerRef.current?.clientWidth`. SSR-safe fallback when ref is null: use a sensible default (e.g., 1280 — the xl breakpoint, matching the most common desktop case).
- Row width inside the container also accounts for the outer wrapper's horizontal padding. The current outer wrapper uses `px-4 py-4` = 16px each side = 32px total horizontal padding. Subtract this from the container width before dividing.
- Computed row height: `Math.round(((containerWidth - 32) / columns) * 1.5)` for the 2:3 aspect.
- Examples at 1280px container width: 3 cols → ~624px row, 5 cols → ~374px, 7 cols → ~267px, 9 cols → ~208px, 11 cols → ~170px. The previous fixed `160` was therefore an underestimate at every breakpoint EXCEPT 11 columns, which is why overlap was visible at every breakpoint below xl.

**Why this closes the gap from HUMAN-UAT Test 4:**
The bug was: `estimateSize: () => 160` returned the same value regardless of column count. At 3 columns, actual row height is ~624px (at 1280px container width), so each row was placed only 160px below the previous one — the visible card div (which honors its `aspect-[2/3]` constraint and renders at its true ~624px height) extended ~464px past the start of the next row, covering the cards below.

Either layer alone would mostly work; both together make the fix robust to font rendering, image-load reflow, and breakpoint transitions.
