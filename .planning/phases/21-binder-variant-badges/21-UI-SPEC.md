## Typography

This phase introduces one new typographic element: the variant badge label on card tiles in binder mode.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label / Badge | 9px (`text-[9px]`) | 700 (bold) | default |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 700 (bold) | 1.2 |

Badge label specifics (source: `manage-trade-card.tsx` lines 93–98, verified):
- Size: `text-[9px]`
- Weight: `font-bold` (700)
- Transform: `uppercase`
- Content: the `variantType` string verbatim (e.g. "FOIL", "SHOWCASE", "PRESTIGE", "HYPERSPACE", "HYPERSPACE FOIL", "SERIALIZED")

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (oklch 1 0 0 light / oklch 0.141 dark) | Page background, surfaces |
| Secondary (30%) | `--card` / `--muted` | Card tiles, sidebar, nav, tile backgrounds |
| Accent (10%) | `--primary` (oklch 0.5 0.134 242.749 light / oklch 0.443 dark — blue) | Primary CTAs, active states, owned count badge |
| Destructive | `--destructive` (oklch 0.577 0.245 27.325 light) | Destructive actions only |

Accent reserved for: primary CTA buttons, active filter chips, owned count badge, hover ring on card tiles.

**Variant badge color contract (locked — D-05):**
- Background: `bg-black/70` — semi-transparent black overlay, independent of theme token
- Foreground: `text-white` — always white regardless of light/dark mode
- Rationale: The badge sits on top of card art. A theme-aware color would be illegible against unpredictable art backgrounds. Semi-transparent black is the established project pattern (matches `manage-trade-card.tsx` lines 93–98).

Source: CONTEXT.md D-05, RESEARCH.md Pattern 4, `src/app/globals.css`

## Component Inventory

### Variant Type Badge — CardItem (binder mode)

This is the only new UI element in Phase 21. It is a plain `<div>` — no shadcn component, no Radix primitive.

**Render condition:** `mode === 'binder' && variantType && variantType !== 'Normal'`

**Position:** `absolute top-1 left-1` — inside the `<div className="relative rounded-md overflow-hidden ...">` image container, which is inside the `<Link>` wrapper. Must NOT be placed outside the `<Link>` block (Pitfall 4 in RESEARCH.md).

**Z-index:** `z-20` — appears above the card image and the hover overlay (`z-10`).

**Exact class string (copy verbatim from `src/components/binder/manage-trade-card.tsx` lines 93–98):**

```
absolute top-1 left-1 bg-black/70 text-white text-[9px] px-1.5 py-0.5 rounded-sm font-bold shadow-md z-20 pointer-events-none uppercase
```

**JSX:**
```tsx
{isBinder && variantType && variantType !== 'Normal' && (
  <div className="absolute top-1 left-1 bg-black/70 text-white text-[9px] px-1.5 py-0.5 rounded-sm font-bold shadow-md z-20 pointer-events-none uppercase">
    {variantType}
  </div>
)}
```

**Props change to `CardItemProps`:**
```typescript
variantType?: string;  // add alongside existing tradeQuantity?: number
```

**No other components change in this phase.** The existing binder-mode `CardItem` badges (green "N Available" pill at `-top-2 -right-2`) are unchanged.

## Interaction Contract

The variant badge is fully non-interactive:
- `pointer-events-none` — does not capture clicks, hovers, or focus
- Does not block the `<Link>` navigation to the card detail page
- Does not appear in or near the hover overlay (z-index ordering: badge at z-20 is above hover overlay at z-10, but the hover overlay covers the full tile; the badge is visible on top of the overlay when hovering)

No new interactive elements are introduced by this phase.

## States

| State | Badge Behavior |
|-------|---------------|
| `variantType` is `undefined` | Badge not rendered |
| `variantType` is `'Normal'` | Badge not rendered |
| `variantType` is any other string | Badge rendered with that string in uppercase |
| `mode` is not `'binder'` | Badge not rendered (condition gates on `isBinder`) |
| Card tile hovered | Badge remains visible above the hover overlay (z-20 > z-10) |
| Card tile not hovered | Badge visible on top of card art |
