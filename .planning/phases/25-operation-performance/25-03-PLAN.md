<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (React state) → API | progress count is rendered client-side from PapaParse output or starterDecks data; does NOT cross to the server |
| Next.js Server Component (page.tsx) ↔ loading.tsx fallback | loading.tsx is rendered without session — must not access any user data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-03-01 | Information Disclosure | loading.tsx skeleton | mitigate | loading.tsx contains NO user data, NO auth check, NO DB call — only static placeholder DOM with Tailwind classes; static-analysis test asserts auth-related imports are absent |
| T-25-03-02 | Spoofing | Progress count displayed before server confirms | accept | The card count shown ("Importing N cards...") is a client-side render of PapaParse output — it represents what WILL be sent, not what the server has received; on error the count remains visible until the error banner replaces it, which is acceptable UX (the actual server result is shown in the success banner) |
| T-25-03-03 | Denial of Service | Massive deck.cards.reduce in handleQuickAdd | accept | starterDecks is a static client-side data file with bounded sizes (largest deck ~70 cards); the reduce runs in O(n) on at most ~100 items — no DoS surface |
| T-25-03-04 | Tampering | loading.tsx caching by client | accept | loading.tsx is a static React component; Next.js handles its rendering — no user input or runtime data flows through it |
</threat_model>
