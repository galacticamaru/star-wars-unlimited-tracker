## Layout: VariantCollectionSection

The "Your Collection" section on the card detail page replaces `<CollectionControls>` with `<VariantCollectionSection>`. The outer shell is identical to the existing container.

```
┌─────────────────────────────────────────────────────┐
│  YOUR COLLECTION                         (section label, xs bold uppercase muted)
│                                                       │
│  Total: 3 copies                         (sm semibold foreground, read-only, BELOW rows)
│  ─────────────────────────────────────────────────── │
│  Normal          [ − ]  [ 2 ]  [ + ]    Owned        │
│  Hyperspace      [ − ]  [ 1 ]  [ + ]    Owned        │
│  Showcase        [ − ]  [ 0 ]  [ + ]    Not owned    │
└─────────────────────────────────────────────────────┘
```

**Total line position:** Below the variant rows (bottom of section). This gives the rows visual primacy — the user interacts with rows first, and the total confirms the result. Placing it at the bottom avoids visual competition with the section label at the top.

**Variant row anatomy:**
- Variant type label (`text-sm text-muted-foreground`, left-aligned, `w-28` min-width for alignment)
- Minus button (`variant="outline"` `size="icon"`, disabled when count === 0)
- Count input (`w-16 text-center font-bold`, type="number")
- Plus button (`variant="outline"` `size="icon"`)
- Status indicator: "Owned" (`text-sm font-semibold text-primary`) when count > 0, "Not owned" (`text-sm font-medium text-muted-foreground`) when count === 0

**Total line anatomy:**
- Label: `text-xs font-semibold text-muted-foreground` — "Total:"
- Value: `text-sm font-semibold text-foreground` — numeric sum
- Separator: `border-t border-border` above the total line, `mt-2 pt-2` spacing
- No +/− controls on total line

**Container:** `flex flex-col gap-2 p-4 bg-muted/50 rounded-lg border border-border` (exact same classes as current CollectionControls wrapper — source: line 42 of collection-controls.tsx)

**Row gap:** `gap-3` between variant rows (within the row itself, between elements: `gap-3` same as CollectionControls)

## Interaction Contract

| Interaction | Behavior | Edge Case |
|-------------|----------|-----------|
| Click + on any variant | `count + 1`, optimistic UI update via `setCounts`, fire `POST /api/collection/variants` | No upper limit enforced by UI |
| Click − on any variant | `count - 1`, optimistic UI update, fire `POST /api/collection/variants` | Button disabled at count === 0; `Math.max(0, newCount)` floor in handler |
| Type in count input | Parse `parseInt(value, 10) || 0`, same optimistic update + fetch | Floor at 0 via `Math.max` |
| Count changes | Total line recalculates as `Object.values(counts).reduce((a,b) => a+b, 0)` — derived from client state, no extra fetch | Always in sync with local state |
| User not authenticated | Redirect to `/login` (same pattern as existing CollectionControls) | Applied per-row; all rows share the same session check |

Optimistic UI pattern: local `useState<Record<number, number>>` keyed by `cardPrintingId`. Initialized from RSC-fetched `ownedCount` per printing. Same fire-and-update approach as existing `CollectionControls` — no rollback on error (log to console, per existing pattern).

Source: `src/components/catalog/collection-controls.tsx` lines 22–38, CONTEXT.md D-11, RESEARCH.md Pattern 5

## States

| State | What User Sees |
|-------|----------------|
| Authenticated, no copies owned | All rows show count 0, − disabled, "Not owned" label. Total: 0 copies. |
| Authenticated, some variants owned | Owned rows show count > 0 with "Owned" label in primary color. Total reflects sum. |
| Unauthenticated | CollectionControls does not render (RSC: userId is null). Section is hidden or replaced by a sign-in prompt (existing behavior — not changed by this phase). |
| Single variant card (only Normal) | Section renders with one row. Total line still shown for consistency. |
| Network error on update | Console.error only (existing pattern). Count remains at optimistic value — no UI error indicator introduced in this phase. |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Section label | YOUR COLLECTION |
| Variant row status (owned) | Owned |
| Variant row status (not owned) | Not owned |
| Total line label | Total: |
| Total line format | Total: {N} copies (e.g. "Total: 3 copies") |
| Aria label — decrease | "Decrease {variantType} owned count" (e.g. "Decrease Normal owned count") |
| Aria label — increase | "Increase {variantType} owned count" (e.g. "Increase Normal owned count") |
| Empty state | Not applicable — all variants are always shown even at 0 (D-09) |
| Error state | No visible error state in this phase — console.error only, matching existing pattern |
| Destructive confirmation | No destructive actions in this phase |

Copywriting rules:
- Variant type labels render exactly as stored in `variantType` column (e.g. "Normal", "Hyperspace", "Showcase"). No transformation other than display as-is.
- "Total: 0 copies" is shown when all variants are 0. Do not hide the total line.
- "copies" is always lowercase, always appended — even for count of 1 ("Total: 1 copies" is acceptable; no singular/plural branching).

## Accessibility

| Requirement | Implementation |
|-------------|----------------|
| Minus button disabled at 0 | `disabled` prop on Button when count === 0 — `disabled:pointer-events-none disabled:opacity-50` via button CVA |
| Aria labels on icon buttons | `aria-label="Decrease {variantType} owned count"` / `aria-label="Increase {variantType} owned count"` |
| Input accessible name | `<Input>` is within a row that visually labels it via the variant type text; add `aria-label="{variantType} owned count"` to the input |
| Read-only total | Rendered as `<p>` or `<span>` — not an input. No interactive affordance. |
