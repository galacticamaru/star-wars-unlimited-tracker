<objective>
Replace the ~8,400 sequential single-row round trips in `upsertCards()` with chunked multi-row upserts, and give `syncAllCards()` the two things the honest-verdict work in 34-07 needs: a single-source non-token set list and a soft deadline that reports what it did not reach.

This is the phase's TRACER slice. After Task 1, `GET /api/cron/sync-cards` — the existing, unchanged route — runs the entire card sync through batched writes end to end: swu-db fetch -> in-memory variant grouping -> chunked `INSERT ... ON CONFLICT DO UPDATE` -> `card_definitions` + `card_printings`. Production quality, no stubs.

Purpose: SYNC-01's timeout is caused entirely by round-trip count. Batching is the fix; everything else in this phase reports on it.
Output: `chunk.ts`, `set-list.ts`, a batched `upsertCards()`, a deadline-aware `syncAllCards()`, and an updated unit test asserting the new call shape.
</objective>

Create `src/lib/sync/chunk.ts` exporting `SYNC_CHUNK_SIZE = 500` and `chunk<T>(items: T[], size: number): T[][]` (slice loop, returns `[]` for an empty input). 500 is the researched value: 500x17 = 8,500 and 500x9 = 4,500 bind parameters, both far under Postgres's 65,535 ceiling, and above the measured per-set averages (~79 definitions, ~254 printings).

Rewrite the body of `upsertCards(setId, cards)` in `src/lib/sync/upsert-cards.ts`. Keep the exported signature, the token-set guard at line 62, the token card-type filter, the `Name|Subtitle` grouping map, and the anchor-selection rule (prefer `VariantType === 'Normal'`, else lexicographically lowest `Set-Number`) exactly as they are today. Replace only the two write loops:

Phase A — collect. Walk the groups once and build two in-memory arrays instead of writing. `definitionRows` gets one entry per group with the identical 17 fields the current single-row insert supplies (`swudbId` = anchor `Set-Number`, `name`, `subtitle`, `type`, `aspects`, `arenas`, `traits`, `keywords`, `cost`, `power`, `hp`, `frontText`, `backText`, `epicAction`, `doubleSided`, `unique`, `updatedAt`). `pendingPrintings` gets one entry per variant carrying its 8 printing fields plus the anchor `swudbId` it belongs to, with `cardDefinitionId` deliberately not yet resolved.

Phase B — de-duplicate. Before chunking, collapse `definitionRows` by `swudbId` and `pendingPrintings` by `setCode + collectorNumber`, last-write-wins. This guard is mandatory and is a new failure mode introduced by batching: Postgres raises "ON CONFLICT DO UPDATE command cannot affect row a second time" when one multi-row statement carries two rows with the same conflict key, whereas today's per-row loop silently tolerates a duplicate from dirty upstream data.

Phase C — write definitions. For each `chunk(definitionRows, SYNC_CHUNK_SIZE)`, skip the chunk when its length is 0, then `db.insert(cardDefinitions).values(chunkArray).onConflictDoUpdate({ target: cardDefinitions.swudbId, set: { ...identical field list to today, all `excluded.*` } }).returning({ id: cardDefinitions.id, swudbId: cardDefinitions.swudbId })`. Keep `updatedAt: sql\`now()\`` on both the values and the conflict-update side — do not hoist a JS `new Date()` outside the loop; the SYNC-04 freshness route derives from this column. Accumulate every returned row into `idBySwudbId: Map<string, number>` keyed by `row.swudbId`. Never index into the returning array positionally — RETURNING order is not contractually the insert order, and a positional read is the single most likely source of a silent cross-linked-card bug in this phase.

Phase D — write printings. Resolve each pending printing's `cardDefinitionId` from `idBySwudbId`. If any lookup misses, throw an Error naming the set and the unresolved `swudbId` rather than writing an orphan or skipping the row. Then `chunk(printingRows, SYNC_CHUNK_SIZE)`, skip empty chunks, and `db.insert(cardPrintings).values(chunkArray).onConflictDoUpdate({ target: [cardPrintings.setCode, cardPrintings.collectorNumber], set: { ...identical field list to today including `cardDefinitionId: sql\`excluded.card_definition_id\`` } })`. Return the total printing-row count, matching today's return contract.

Update `__tests__/upsert-cards.test.ts` for the new call shape. `mockValues` now receives an array, so every assertion that reads `call[0]` as an object must read `(call[0] as unknown[])[0]`. `mockReturning` must resolve to rows echoing each inserted row's `swudbId` (derive it from the array the mock was called with) rather than the fixed `[{ id: 1 }]`, otherwise the printing lookup will not resolve. Extend the mocked `@/db/schema` with the extra `cardDefinitions` / `cardPrintings` column keys the new code touches. Keep every existing test's intent green (`insertCalls` is still 2 for a single non-token card; the Normal+Hyperspace grouping test still expects one definitions row and two printings rows, now inside one array each; `TS26` still returns 1). Add four new tests: (1) a set of 501 distinct card groups produces exactly 2 definitions inserts with array lengths 500 and 1; (2) exactly 500 groups produces exactly 1 definitions insert; (3) an empty card array and an all-token card array both produce 0 insert calls and return 0; (4) a `mockReturning` that deliberately reverses the returned row order still yields printings whose `cardDefinitionId` matches their own anchor's id.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-34-01 | Tampering | `upsertCards()` printings linkage | high | mitigate | Build `idBySwudbId` from the RETURNING row's `swudbId` column, never a positional index; throw on an unresolved lookup instead of writing an orphan. Asserted by the reversed-RETURNING test |
| T-34-02 | Tampering | Batched `INSERT ... ON CONFLICT` | high | mitigate | De-duplicate rows by conflict key before chunking, preventing the "cannot affect row a second time" abort that would fail a whole set from one dirty upstream duplicate |
| T-34-03 | Tampering | Drizzle value interpolation | medium | mitigate | Every swu-db-derived value is passed through Drizzle's `.values()` parameter binding; `sql\`\`` is used only for the fixed `now()` and `excluded.*` fragments, never with interpolated API data. Canon injection coverage is `/gsd-secure-phase` + `eslint`; not re-minted as a prohibition |
| T-34-04 | Denial of Service | Single oversized set chunk | medium | accept | Chunk size 500 caps bind parameters at 8,500 of 65,535; an outsized set costs extra round trips but cannot exceed the statement limit.
