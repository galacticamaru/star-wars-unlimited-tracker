  <action>
Create `src/app/api/cron/sync-status/route.ts` exporting an async `GET(request: NextRequest)`.

Open with the auth guard copied verbatim from `src/app/api/cron/sync-cards/route.ts:7-14`: read `authorization` off `request.headers`, read `process.env.CRON_SECRET`, and return `new Response('Unauthorized', { status: 401 })` when the secret is falsy OR the header does not exactly equal `` `Bearer ${cronSecret}` ``. Preserve the falsy-secret check first — an unset or empty `CRON_SECRET` must fail closed, never open. Do not weaken this into a query-string secret, a header-optional path, or a development-mode bypass.

Export `const FRESH_WINDOW_HOURS = 24` and use it as the single staleness threshold, matching SYNC-02's window.

Query the database exactly once: select `setCode: cardPrintings.setCode` and `` lastSyncedAt: sql<string>`max(${cardPrintings.updatedAt})` `` from `cardPrintings`, grouped by `cardPrintings.setCode`, ordered by `cardPrintings.setCode` ascending. The `orderBy` is load-bearing, not cosmetic: Postgres does not guarantee `GROUP BY` output order, and an unordered array would make two identical calls return different bodies.

Map each row to `{ setCode, lastSyncedAt, ageHours, stale }`. Compute `ageHours` as `(Date.now() - new Date(lastSyncedAt).getTime()) / 3_600_000`, rounded to two decimal places for readability. Set `stale` with a strict `ageHours > FRESH_WINDOW_HOURS` comparison — a set at exactly 24.00 hours is fresh, one at 24.01 is stale.

Compute the top-level verdict as `sets.length > 0 && sets.every(s => !s.stale)`. The `sets.length > 0` term is mandatory: `Array.prototype.every` returns true for an empty array, so without it a completely empty `card_printings` table would report a perfectly fresh catalog. That is the same "absence of evidence read as success" failure the whole phase exists to remove.

Return `Response.json({ fresh, checkedAt: <ISO timestamp>, sets })`. The body must contain nothing else — no connection details, no row counts from other tables, no raw error text.

Perform no outbound `fetch` of any kind (D-04). Wrap the query in a try/catch that logs with `console.error('Sync status failed:', error)` and returns `new Response('Sync status failed', { status: 500 })` — a generic message matching the existing convention, never the caught error object, and never the Authorization header or `CRON_SECRET` value in any log line.
  </action>

<flagged_assumptions>
**Design limitation, recorded not hidden (not probe-derived; carried forward, does not close a probe row).** D-02 derives freshness from rows that exist in `card_printings`, and D-04 forbids fetching the upstream set list. A non-token set that has *never* synced therefore has no rows at all and does not appear in the response — its absence, not a `stale: true` flag, is the only available signal. Closing that hole requires either upstream count verification or a sync-run history table, both explicitly deferred (CONTEXT § Deferred Ideas). The `sets.length > 0` guard covers the catastrophic case (an entirely empty catalog); the per-set case is a known, accepted residual.
