  <action>
Change `vitest.config.mts` from the object form to the function form so Vite's `mode` is available: `export default defineConfig(({ mode }) => ({ ... }))`. Import `loadEnv` from `vite` and add `env: loadEnv(mode, process.cwd(), 'DATABASE_')` inside the `test` block. Scope the prefix to `DATABASE_` rather than the empty string that would load every variable in `.env.local` — this is least privilege, and `DATABASE_URL` is the only value the new test needs. Leave `plugins`, `environment`, `globals` and `passWithNoTests` unchanged.

Create `__tests__/starter-decks-resolve.test.ts` with the `// @vitest-environment node` pragma. This is the one test file in the repo that must NOT mock `@/db` — proving the data against a real catalog is its entire purpose.

Structure it as follows. Import `starterDecks` from `@/data/starter-decks`, `db` from `@/db`, `cardPrintings` from `@/db/schema`, and `inArray` / `eq` / `and` from `drizzle-orm`.

Guard first, loudly. In a `beforeAll`, assert `process.env.DATABASE_URL` is a non-empty string, failing with a message that names the cause and the fix (that the `loadEnv` config change supplies it from `.env.local`). Do not gate the check behind a skip modifier or a conditional early return — a check that cannot run must go red, never green. Then assert `starterDecks.length > 0` and that the flattened collector-number list has length greater than zero, so an emptied data file cannot produce a vacuous pass. Never compare the deck array's length to a fixed number: the figure quoted in CONTEXT is stale and any hardcoded count is wrong on day one. Scope everything to `starterDecks.flatMap(...)`.

Build the query input by flattening every deck's cards into `(deckId, collectorNumber)` pairs, then de-duplicating the collector numbers for the query while keeping the full pair list for attribution. Issue one read: select `collectorNumber` from `cardPrintings` where `collectorNumber` is `inArray` the de-duplicated list AND `variantType` equals `'Normal'`. The `variantType` filter is mandatory and must match `starter-deck/route.ts` exactly — without it the test would pass on a number the runtime route still skips, which is precisely the class of false assurance this phase exists to remove. Chunk the `inArray` list at 500 using `chunk` and `SYNC_CHUNK_SIZE` from `@/lib/sync/chunk` (created in 34-01), since 746 unique numbers is already above a comfortable single-statement size and the helper exists.

Assert by producing a full report, not a first-failure abort: build `unresolved` as every `(deckId, collectorNumber)` pair whose number is absent from the resolved set, sorted by `deckId` then `collectorNumber` so the output is deterministic across runs. A collector number referenced by several decks appears once in the query and once per referencing deck in the report. Assert `unresolved` is an empty array, and format the failure message as one line per pair so a red run names every problem at once.

Perform only reads. This test file must contain no insert, update, delete, or schema call of any kind.

Add an `afterAll` that closes the database connection so the Vitest worker exits — the WebSocket `Pool` in `src/db/index.ts` keeps the process alive otherwise. Do not terminate the Node process from inside a test file: forcing an exit is correct for the standalone `tsx` scripts in `scripts/` but would abort sibling test files sharing the Vitest worker. If `src/db/index.ts` does not currently export the `Pool` instance, export it alongside `db` so the test can close it; that export is additive and breaks no existing importer.

Also add a focused negative test that does not need the database: given a synthetic resolved set that contains a number only as a non-Normal variant, the pair-attribution and unresolved-report helpers must classify it as unresolved. Extract those helpers as small pure functions in the test file so this is testable without a second round trip.
