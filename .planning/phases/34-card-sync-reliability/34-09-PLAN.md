<objective>
Close G-34-1, the single blocker in `34-UAT.md`: `buildCaseUpdate()` in `src/lib/sync/prices.ts`
binds each CASE branch value as an untyped parameter. Postgres resolves a CASE expression's result
type from its own branches — an untyped `$n` defaults to `text` — before checking that type against
the assignment target, so every price UPDATE against the `integer` columns `price_eur` / `price_usd`
dies at parse analysis with SQLSTATE 42804. The per-set `try/catch` in `syncPrices()` catches it and
records the set in `failedSets`, which is why a run reports an honest `success: false` with
`setsProcessed: 25/35` instead of crashing. The 25 "processed" sets are promo/OP sets that legitimately
return zero cards upstream; the 10 that failed are every set that actually has cards. Net effect:
**price sync has never written a single price.**

The fix is one cast per branch, already verified against the live database during diagnosis (set SOR
went from `failedSets: [SOR]`, `totalUpdated: 0` to `setsProcessed: 1/1`, `totalUpdated: 252`) and
since reverted — the defect is present at HEAD and this plan re-applies it.

The fix alone is not the deliverable. `src/lib/sync/prices.test.ts` mocks `@/db` entirely, so
`buildCaseUpdate()`'s SQL is never executed by Postgres; the suite passed and `34-VERIFICATION.md`
scored 9/9 while the real UPDATE was type-invalid for every non-empty set. This plan closes the
blind spot with a guard that fails if the cast is ever removed, and corrects the docstring whose
false premise the implementation was built on.

This is a NARROW defect fix. Plans 34-01 through 34-08 are complete and their files are the
historical execution record — do not modify them.

Purpose: the phase exists to make the nightly sync finish and say so when it doesn't. It currently
says so, accurately, about a half that never worked. Make that half work.
Output: a type-correct `buildCaseUpdate()`, a truthful docstring, a database-backed regression guard
that goes red against current HEAD, an honest manual-trigger script, and a real run proving prices
land.
</objective>
