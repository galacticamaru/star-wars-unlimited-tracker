<objective>
Confirm the one number this phase's entire timing design rests on, before 34-07 writes it into code.

D-09 requires `maxDuration` to be set explicitly on the cron route and defers the value to research. Research returned 300 seconds with HIGH confidence for Vercel Hobby *with Fluid Compute*, which has been the platform default since April 2025 — but could not confirm from the repository whether this specific project, created well before that rollout, was auto-migrated or still needs a manual toggle. `vercel.json` does not surface the setting; it is project-level.

Purpose: D-08's soft deadline is 80% of `maxDuration`. If the real ceiling is the legacy 60 seconds rather than 300, a 240-second soft deadline never fires, the function is killed with no response at all, and the phase silently reintroduces the exact partial-run-that-looks-complete failure it exists to remove. Picking this number wrong is not a performance issue; it is a correctness issue.
Output: a one-page `34-BUDGET.md` recording the confirmed ceiling, which 34-07 reads.
</objective>
