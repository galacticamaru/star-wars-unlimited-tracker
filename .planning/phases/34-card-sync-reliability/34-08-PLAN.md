<objective>
Close both gaps recorded in `34-VERIFICATION.md`. They are one root cause: `syncAllCards()`'s per-set
loop body in `src/lib/sync/upsert-cards.ts` has no try/catch, unlike `syncPrices()` in
`src/lib/sync/prices.ts`, so a rejected `fetch()`, a malformed JSON body, a DB write error, or the
deliberate unresolved-swudbId throw inside `upsertCards()` propagates uncaught out of the function.
The cron route's outer catch then fires instead of the honest `cardsOk`/`pricesOk` verdict this phase
built — returning a bodyless `Sync failed` 500, skipping `syncPrices()` entirely, and discarding
`revalidateTag()` for the sets that did land.

This restores D-05 (a set that fails does not abort the run) and D-07 (one verdict covers cards and
prices, and the body names which half broke) for the one failure class that currently escapes them.

This is a NARROW defect fix, not a re-do of the phase. Plans 34-01 through 34-07 are complete and
their files are the historical execution record — do not modify them.

Purpose: the phase goal names honest reporting of an unfinished run as its whole purpose. For this
failure class the run is currently dishonest by omission — it reports nothing at all.
Output: a per-set-isolated `syncAllCards()`, four tests that fail against current HEAD and pass after
the fix, two route-level regression guards, and a recorded deferral of the non-blocking warnings.
</objective>
